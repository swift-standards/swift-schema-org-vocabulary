# swift-schema-org-vocabulary

Use this package when you describe a page, an app, a product or a person with schema.org structured data, or read such data back. The whole schema.org 30.1 vocabulary is here as values under `Schema_Org`, also spelled `SchemaOrg`: every type is a `SchemaOrg.Class` with its parents, every property a `SchemaOrg.Property` with its domains and ranges, and every enumeration member a `SchemaOrg.Member` with its types, so `.softwareApplication`, `.offers` and `.inStock` are the schema.org terms of those names. Build a node from them, as in `JSONLD.Document(SchemaOrg.Node.softwareApplication(.name(app.name), .url(.url(app.page)), .operatingSystem("macOS"), .offers(.offer(.price(0))))).bytes`, read nodes back with `SchemaOrg.Node.instances(of:in:)` and `node[.offers]`, and check a node against the vocabulary's domains and ranges with `findings`. The JSON-LD itself comes from swift-w3c-json-ld. Types, properties and members are structs, not enums, because schema.org is open: releases and extensions add terms, and its domains and ranges are the types it expects, not a closed set, which is why the compiler does not reject a value outside them and `findings` reports it instead. The terms are generated from schema.org's own release file, `schemaorg-current-https.jsonld` of version 30.1 (16 September 2026), pending and extension terms included, into the six files of `Sources/Schema Org Vocabulary/Generated`, by this package's `Schema Org Vocabulary Generator` executable, so that regenerating needs nothing but Swift: it reads the file with swift-rfc-8259 and writes through the C library, without Foundation, and it is not a product, so depending on the library never builds it. To regenerate, take `data/releases/30.1/schemaorg-current-https.jsonld` from the schemaorg/schemaorg repository and run `swift run "Schema Org Vocabulary Generator" schemaorg-current-https.jsonld "Sources/Schema Org Vocabulary/Generated"`.

## Laws

- `SchemaOrg.version` is the schema.org release the terms were generated from.
- Running `Schema Org Vocabulary Generator` on the 30.1 release file writes exactly the files in `Sources/Schema Org Vocabulary/Generated`, byte for byte.
- Every `schema:` class of the release is a static `SchemaOrg.Class`, every `schema:` property a static `SchemaOrg.Property`, and every individual typed by a `schema:` class a static `SchemaOrg.Member`. The static's name is the term with its leading capitals lowercased, `SoftwareApplication` as `softwareApplication`, `URL` as `url` and `EUEnergyEfficiencyEnumeration` as `euEnergyEfficiencyEnumeration`, in backticks where Swift needs them, as `` `3DModel` `` and `` `class` ``.
- A class's `parents` are its `rdfs:subClassOf` classes, a property's `domains` and `ranges` its `domainIncludes` and `rangeIncludes`, and a member's `classes` its types, each limited to `schema:` terms and sorted by term.
- Terms are equal when their names are equal. `named(_:)` gives the vocabulary's term of that name, and for a class or property outside the vocabulary a term with no relations. `isSubclass(of:)` holds for the class itself and every ancestor.
- Each class that is not a data type has a builder on `SchemaOrg.Node` and on `SchemaOrg.Value`, and each property a builder on `SchemaOrg.Assignment` that takes any number of values. A node is written with its `@type`, then its properties in the order they were given, inside a document with the context `https://schema.org`.
- A value is written as JSON-LD: text and URLs as strings, numbers as numbers, a whole `Double` as an integer, `Bool` as a boolean, dates, times and durations in their ISO 8601 forms, a member as its full `https://schema.org/` IRI and a node as a node.
- A member reads from its full IRI, from `http://schema.org/`, from a `schema:` name, from a bare name and from a node holding only that `@id`. A boolean also reads from `True` and `False`, and a number from a string that holds one.
- Reading a document expands it with `SchemaOrg.loader`, which knows schema.org's context by its IRIs and maps it to the `http://schema.org/` vocabulary, as schema.org's own context does, with `id` and `type` as aliases. It then writes `http://schema.org/` IRIs as `https://schema.org/` and gives schema.org terms their plain names. Other IRIs and properties stay as they are.
- `instances(of:in:)` gives the document's nodes whose types include that class or one below it.
- `findings` lists, for each property of the vocabulary on a node, a `domain` finding when the node has types and none of them is in the property's domains, and a `range` finding for each value that fits none of its ranges. A typed node fits the classes it is an instance of, a node without a type fits every class that is not a data type and URL, a member fits its classes, a boolean fits Boolean, a number and a string holding one fit Number and below it, and any other string fits the text, date, time and quantity data types. Every value fits DataType. Properties outside the vocabulary are not checked.
